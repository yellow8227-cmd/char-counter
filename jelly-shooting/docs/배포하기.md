# 올리기 · 아이콘 · 링크 미리보기

## 무엇을 올려야 하나

`jelly-shooting/` 폴더를 통째로 올린다. `tools/` 와 `docs/` 는 개발용이라 없어도 되지만
있어도 상관없다. **반드시 같이 올라가야 하는 것**:

```
index.html
manifest.json
sw.js
apple-touch-icon.png  icon-192.png  icon-512.png  icon-maskable-512.png
favicon-32.png  og.png
fonts/Griun_Donguri-Rg.ttf  fonts/Griun_NoltoTAENGGU-Rg.ttf   ← 없으면 기본 글꼴로 보인다
```

**https 여야 한다.** 온라인 대전(Supabase Realtime)과 홈 화면 추가, 링크 미리보기가
모두 https에서만 제대로 동작한다.

## 홈 화면에 추가했는데 회색 빈 칸이 나올 때

아이폰은 `apple-touch-icon.png` 가 **404면 페이지를 스크린샷 떠서 아이콘으로 쓴다.**
첫 화면이 흰 배경이 많아서 회색 빈 칸처럼 보인다. 아이콘 파일이 실제로 올라갔는지
주소창에 직접 쳐서 확인한다:

```
https://zingy-cupcake-98444a.netlify.app/apple-touch-icon.png
```

그림이 보이면 정상이다. 그래도 회색이면 홈 화면 아이콘을 지우고 다시 추가한다
(iOS는 아이콘을 한 번 정하면 캐시한다).

아이콘을 다시 만들려면 — 캐릭터 그림을 고쳤을 때:

```bash
node jelly-shooting/tools/make-icons.mjs
```

게임의 `drawAvatar()` 를 그대로 불러 그리므로 게임 그림과 항상 같다.

## 링크를 보낼 때 미리보기 그림이 안 뜰 때

미리보기(`og:image`)는 **크롤러가 자바스크립트를 돌리지 않으므로 HTML에 박힌 절대
주소만 본다.** 배포 주소가 바뀌면 그 주소도 같이 바꿔야 한다:

현재 주소는 **https://zingy-cupcake-98444a.netlify.app** 로 맞춰져 있다.
주소가 바뀌면 손으로 고치지 말고:

```bash
node jelly-shooting/tools/set-site-url.mjs https://새주소
node jelly-shooting/tools/set-site-url.mjs            # 지금 값 보기
```

**폴더 안의 내용이 사이트 루트에 놓여야 한다.** `jelly-shooting` 폴더 자체를 드래그하면
Netlify가 그 안의 내용을 루트로 올려 주므로 `.../og.png` 로 열린다. 실수로 상위 폴더를
올리면 `.../jelly-shooting/og.png` 가 되어 미리보기가 깨진다 — 그때는 그 주소로 다시
맞추면 된다.

### 그림을 바꿨는데도 예전 미리보기가 뜰 때 — 순서대로 확인

**1. 새 파일이 진짜 올라갔는가.** 주소창에 직접 쳐 본다:

```
https://zingy-cupcake-98444a.netlify.app/og.png?v=99
```

`?v=99` 를 붙이는 이유: 그냥 `/og.png` 로 열면 **내 브라우저 캐시와 서비스워커**가
예전 그림을 그대로 보여줘서 "안 올라갔다"고 오진하게 된다.

- 예전 그림이 보인다 → **아직 안 올라갔다.** 폴더를 다시 올린다
- 404 가 뜬다 → 파일이 빠졌거나 폴더를 한 겹 더 감싸서 올렸다
  (`.../jelly-shooting/og.png` 로도 열어 본다)
- 새 그림이 보인다 → 파일은 올라갔다. 아래 2번으로

**2. 받는 쪽(카카오·트위터) 캐시.** 링크에 `?v=2` 를 붙여 한 번 보내면 페이지를 새로
읽는다. 그런데 **그림 주소가 그대로면 그림은 예전 것을 그냥 다시 쓴다** — 같은 주소면
같은 그림으로 보기 때문이다. 그래서 `og:image` 주소 자체에 판 번호를 붙여 둔다:

```
og:image = .../og.png?v=2
```

그림을 또 바꿨는데 예전 것이 계속 뜨면 `tools/set-site-url.mjs` 안의 `IMG_VER` 를
올리고 다시 돌린다. 주소가 달라지니 캐시가 이길 수 없다.

**2-b. 카카오 캐시를 직접 지우는 방법 (가장 확실하다).**
카카오가 공식 도구를 준다. 로그인해서 주소를 넣고 캐시 삭제를 누르면 그 자리에서 다시 읽는다:

```
https://developers.kakao.com/tool/clear/og
```

로그인이 번거로우면 **한 번도 안 보낸 주소**로 보내면 된다 — 카카오는 주소별로 캐시하므로
`?v=3`, `?v=4` 처럼 숫자를 바꿔 보내면 새 주소로 취급해 새로 읽는다. 단, 예전에
`?v=2` 를 이미 보냈다면 그 주소도 캐시돼 있으니 안 쓴 숫자를 골라야 한다.

**2-c. 그림이 무거우면 크롤러가 포기한다.**
`og.png` 는 1.1MB 다. 크롤러는 기다려 주지 않는다 — 받다가 시간이 지나면 예전 그림을
그냥 쓴다. 그래서 같은 그림을 **JPEG(114KB)** 로도 뽑아 `og:image` 는 그쪽을 가리킨다.
`make-og.mjs` 를 돌리면 `og.png` 와 `og.jpg` 가 같이 나온다. **둘 다 올려야 한다.**

**3. 아이폰 홈 화면 아이콘은 따로다.** 한 번 정해지면 iOS가 캐시한다.
아이콘을 지우고 다시 추가해야 새 아이콘이 나온다.

## 미리보기 카드(og.png) 다시 만들기

```bash
node jelly-shooting/tools/make-og.mjs                      # og.png 갱신
node jelly-shooting/tools/make-og.mjs --out /tmp/시험.png   # 원본 안 건드리고 시험
```

**배치를 바꾸려면** `tools/make-og.mjs` 안의 `── 여기만 만지면 배치가 바뀐다 ──` 블록만
고치면 된다 — 소실점(`VX/VY`), 앞쪽 물체 크기(`R0`), 주인공 위치(`HERO`),
날아오는 것들의 목록(`FLY`: 각도·거리·종류·색).

확정된 방향과 **시도했다가 버린 것들**은 그 파일 맨 위 주석에 적어 뒀다. 다음에 손볼 때
같은 함정을 다시 밟지 않도록 꼭 먼저 읽자. 요약하면:

- 그림에 글자를 넣지 않는다 (제목·설명은 미리보기 카드가 아래에 붙여 준다)
- 대표 캐릭터는 분홍 고양이 하나. 여럿 세우면 시선이 갈 곳이 없다
- 입체감은 다섯 겹(그림자 · 옮긴 방사 그라데이션 · 속 빛 · 림+테두리 그늘 · 광택)
- '날아온다'는 소실점 + 원근(t*t) + 잔상, 그리고 제일 가까운 것의 초점 흐림
- 캐릭터에도 젤리와 같은 입체 처리를 얹어야 한다. 안 하면 캐릭터만 종이처럼 납작하다

아이콘(`make-icons.mjs`)과 카드(`make-og.mjs`)는 둘 다 게임의 `drawAvatar()` 를 그대로
불러 쓴다. 그래서 캐릭터 그림을 고치면 아이콘·카드도 다시 돌리기만 하면 따라온다.

## 게임을 고쳐 올렸는데 예전 화면이 나올 때

서비스워커가 예전 파일을 캐시하고 있다. `sw.js` 맨 위의 버전을 올린다:

```js
const CACHE = 'jelly-v29';   // → 'jelly-v30'
```

이걸 안 올리면 방문자에게 새 버전이 안 간다.

## 랭킹에 남의 프로필 사진까지 보이게 하기 (Supabase 한 줄)

대기실(방 안)에서는 아무 설정 없이 서로의 얼굴이 보입니다 — 차림새를 방 메시지로
직접 주고받기 때문입니다.

**온라인 랭킹**은 다릅니다. 지금 접속해 있지 않은 사람의 얼굴이니 DB에 저장돼 있어야
합니다. `scores` 표에 차림새를 담을 칸이 하나 필요합니다.

1. Supabase → 왼쪽 메뉴 **SQL Editor** → **New query**
2. 아래 한 줄을 붙여넣고 **Run**

```sql
alter table scores add column if not exists ch text;
```

끝입니다. 게임은 고칠 필요가 없습니다 — 칸이 생기면 다음 판부터 얼굴을 같이 올리고,
랭킹에서 남의 얼굴이 보이기 시작합니다.

**이 줄을 안 돌려도 아무것도 고장나지 않습니다.** 게임은 칸이 있는지 한 번 써 보고
없으면 이름·점수만 올립니다(점수를 잃지 않습니다). 랭킹에는 내 얼굴만 보입니다.

칸이 생기기 **전에 올라간 기록**에는 차림새가 없으니 그 줄은 계속 이름만 나옵니다.
그 사람이 다시 한 판 하면 얼굴이 붙습니다.

담기는 값은 `{"k":"bear","c":"#c9a27a","a":"crown","ac":"#ffce3d"}` 같은 60~70바이트
짜리 짧은 글입니다(종류·색·악세서리·악세서리 색, 나만의 악세서리면 모양 이모지까지).
받아서 그릴 때는 아는 값만 통과시키고 모르는 값은 기본 캐릭터로 떨어뜨립니다.

## 💬 채팅은 따로 설정할 게 없습니다

월드 채팅(`jelly:chat:kr`)과 방 채팅은 이미 쓰고 있는 **Supabase Realtime broadcast** 를
그대로 씁니다. 표를 만들 필요도, SQL 을 돌릴 필요도 없습니다.

대신 **지나간 이야기는 보관되지 않습니다.** broadcast 는 서버에 저장하지 않으므로
들어온 뒤부터 보이고, 화면을 닫으면 사라집니다(그 점을 화면에 적어 두었습니다).
기록을 남기려면 표를 하나 만들어야 하는데, 그러면 신고·삭제 같은 관리가 따라옵니다.

넣어 둔 안전장치: 한 마디 60자 · 1.2초에 한 번만 · 줄바꿈·제어문자 제거 ·
닉네임 없으면 못 보냄 · 화면에는 글자로만 넣어 HTML 이 태그로 안 들어감.

## 🔁 같은 친구랑 한 판 더

판이 끝나도 방 채널은 그대로 붙어 있습니다. 결과 화면의 **🔁 (친구이름)랑 다시** 를 누르면
같은 방의 대기실로 돌아가고, 상대에게도 알려서 같이 돌아옵니다. 방을 다시 팔 필요가 없습니다.
(준비·점수·탈락 순서만 비우고, 방장은 다음 판 씨앗을 새로 뽑습니다.)

## ↩️ 메시지 회수

내 말 옆의 **회수** 를 누르면 내 화면과 상대 화면에서 함께 사라집니다.
broadcast 에는 '누가 보냈는지'를 서버가 보증해 주지 않으므로, 지울 때도 이름을 같이 보고
**그 말의 주인과 같을 때만** 지웁니다(채팅 자체와 같은 수준의 믿음입니다).
지나간 말은 어차피 서버에 저장되지 않으니, 회수는 '지금 화면에 보이는 것'을 거두는 것입니다.
