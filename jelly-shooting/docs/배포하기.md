drop policy if exists players_insert_own on players;

## 링크를 보낼 때 미리보기 그림이 안 뜰 때

미리보기(`og:image`)는 **크롤러가 자바스크립트를 돌리지 않으므로 HTML에 박힌 절대
주소만 본다.** 배포 주소가 바뀌면 그 주소도 같이 바꿔야 한다:

현재 주소는 **https://zingy-cupcake-98444a.netlify.app** 로 맞춰져 있다.
주소가 바뀌면 손으로 고치지 말고:

```bash
node jelly-shooting/tools/set-site-url.mjs https://새주소
node jelly-shooting/tools/set-site-url.mjs            # 지금 값 보기
```

**폴더 안의 내용이 사이트 루트에 놓여야 한다.** `jelly-shooting` 폴더 자체를 드래그하면
Netlify가 그 안의 내용을 루트로 올려 주므로 `.../og.png` 로 열린다. 실수로 상위 폴더를
올리면 `.../jelly-shooting/og.png` 가 되어 미리보기가 깨진다 — 그때는 그 주소로 다시
맞추면 된다.

### 그림을 바꿨는데도 예전 미리보기가 뜰 때 — 순서대로 확인

**1. 새 파일이 진짜 올라갔는가.** 주소창에 직접 쳐 본다:

```
https://zingy-cupcake-98444a.netlify.app/og.png?v=99
```

`?v=99` 를 붙이는 이유: 그냥 `/og.png` 로 열면 **내 브라우저 캐시와 서비스워커**가
예전 그림을 그대로 보여줘서 "안 올라갔다"고 오진하게 된다.

- 예전 그림이 보인다 → **아직 안 올라갔다.** 폴더를 다시 올린다
- 404 가 뜬다 → 파일이 빠졌거나 폴더를 한 겹 더 감싸서 올렸다
  (`.../jelly-shooting/og.png` 로도 열어 본다)
- 새 그림이 보인다 → 파일은 올라갔다. 아래 2번으로

**2. 받는 쪽(카카오·트위터) 캐시.** 링크에 `?v=2` 를 붙여 한 번 보내면 페이지를 새로
읽는다. 그런데 **그림 주소가 그대로면 그림은 예전 것을 그냥 다시 쓴다** — 같은 주소면
같은 그림으로 보기 때문이다. 그래서 `og:image` 주소 자체에 판 번호를 붙여 둔다:

```
og:image = .../og.png?v=2
```

그림을 또 바꿨는데 예전 것이 계속 뜨면 `tools/set-site-url.mjs` 안의 `IMG_VER` 를
올리고 다시 돌린다. 주소가 달라지니 캐시가 이길 수 없다.

**2-b. 카카오 캐시를 직접 지우는 방법 (가장 확실하다).**
카카오가 공식 도구를 준다. 로그인해서 주소를 넣고 캐시 삭제를 누르면 그 자리에서 다시 읽는다:

```
https://developers.kakao.com/tool/clear/og
```

로그인이 번거로우면 **한 번도 안 보낸 주소**로 보내면 된다 — 카카오는 주소별로 캐시하므로
`?v=3`, `?v=4` 처럼 숫자를 바꿔 보내면 새 주소로 취급해 새로 읽는다. 단, 예전에
`?v=2` 를 이미 보냈다면 그 주소도 캐시돼 있으니 안 쓴 숫자를 골라야 한다.

**2-c. 그림이 무거우면 크롤러가 포기한다.**
`og.png` 는 1.1MB 다. 크롤러는 기다려 주지 않는다 — 받다가 시간이 지나면 예전 그림을
그냥 쓴다. 그래서 같은 그림을 **JPEG(114KB)** 로도 뽑아 `og:image` 는 그쪽을 가리킨다.
`make-og.mjs` 를 돌리면 `og.png` 와 `og.jpg` 가 같이 나온다. **둘 다 올려야 한다.**

**3. 아이폰 홈 화면 아이콘은 따로다.** 한 번 정해지면 iOS가 캐시한다.
아이콘을 지우고 다시 추가해야 새 아이콘이 나온다.

## 미리보기 카드(og.png) 다시 만들기

```bash
node jelly-shooting/tools/make-og.mjs                      # og.png 갱신
node jelly-shooting/tools/make-og.mjs --out /tmp/시험.png   # 원본 안 건드리고 시험
```

**배치를 바꾸려면** `tools/make-og.mjs` 안의 `── 여기만 만지면 배치가 바뀐다 ──` 블록만
고치면 된다 — 소실점(`VX/VY`), 앞쪽 물체 크기(`R0`), 주인공 위치(`HERO`),
날아오는 것들의 목록(`FLY`: 각도·거리·종류·색).

확정된 방향과 **시도했다가 버린 것들**은 그 파일 맨 위 주석에 적어 뒀다. 다음에 손볼 때
같은 함정을 다시 밟지 않도록 꼭 먼저 읽자. 요약하면:

- 그림에 글자를 넣지 않는다 (제목·설명은 미리보기 카드가 아래에 붙여 준다)
- 대표 캐릭터는 분홍 고양이 하나. 여럿 세우면 시선이 갈 곳이 없다
- 입체감은 다섯 겹(그림자 · 옮긴 방사 그라데이션 · 속 빛 · 림+테두리 그늘 · 광택)
- '날아온다'는 소실점 + 원근(t*t) + 잔상, 그리고 제일 가까운 것의 초점 흐림
- 캐릭터에도 젤리와 같은 입체 처리를 얹어야 한다. 안 하면 캐릭터만 종이처럼 납작하다

아이콘(`make-icons.mjs`)과 카드(`make-og.mjs`)는 둘 다 게임의 `drawAvatar()` 를 그대로
불러 쓴다. 그래서 캐릭터 그림을 고치면 아이콘·카드도 다시 돌리기만 하면 따라온다.

## 랭킹에 남의 프로필 사진까지 보이게 하기 (Supabase 한 줄)

대기실(방 안)에서는 아무 설정 없이 서로의 얼굴이 보입니다 — 차림새를 방 메시지로
직접 주고받기 때문입니다.

**온라인 랭킹**은 다릅니다. 지금 접속해 있지 않은 사람의 얼굴이니 DB에 저장돼 있어야
합니다. `scores` 표에 차림새를 담을 칸이 하나 필요합니다.

1. Supabase → 왼쪽 메뉴 **SQL Editor** → **New query**
2. 아래 한 줄을 붙여넣고 **Run**

```sql
alter table scores add column if not exists ch text;
```

끝입니다. 게임은 고칠 필요가 없습니다 — 칸이 생기면 다음 판부터 얼굴을 같이 올리고,
랭킹에서 남의 얼굴이 보이기 시작합니다.

**이 줄을 안 돌려도 아무것도 고장나지 않습니다.** 게임은 칸이 있는지 한 번 써 보고
없으면 이름·점수만 올립니다(점수를 잃지 않습니다). 랭킹에는 내 얼굴만 보입니다.

칸이 생기기 **전에 올라간 기록**에는 차림새가 없으니 그 줄은 계속 이름만 나옵니다.
그 사람이 다시 한 판 하면 얼굴이 붙습니다.

담기는 값은 `{"k":"bear","c":"#c9a27a","a":"crown","ac":"#ffce3d"}` 같은 60~70바이트
짜리 짧은 글입니다(종류·색·악세서리·악세서리 색, 나만의 악세서리면 모양 이모지까지).
받아서 그릴 때는 아는 값만 통과시키고 모르는 값은 기본 캐릭터로 떨어뜨립니다.

## 💬 채팅은 따로 설정할 게 없습니다

월드 채팅(`jelly:chat:kr`)과 방 채팅은 이미 쓰고 있는 **Supabase Realtime broadcast** 를
그대로 씁니다. 표를 만들 필요도, SQL 을 돌릴 필요도 없습니다.

대신 **지나간 이야기는 보관되지 않습니다.** broadcast 는 서버에 저장하지 않으므로
들어온 뒤부터 보이고, 화면을 닫으면 사라집니다(그 점을 화면에 적어 두었습니다).
기록을 남기려면 표를 하나 만들어야 하는데, 그러면 신고·삭제 같은 관리가 따라옵니다.

넣어 둔 안전장치: 한 마디 60자 · 1.2초에 한 번만 · 줄바꿈·제어문자 제거 ·
닉네임 없으면 못 보냄 · 화면에는 글자로만 넣어 HTML 이 태그로 안 들어감.

## ↩️ 메시지 회수

내 말 옆의 **회수** 를 누르면 내 화면과 상대 화면에서 함께 사라집니다.
broadcast 에는 '누가 보냈는지'를 서버가 보증해 주지 않으므로, 지울 때도 이름을 같이 보고
**그 말의 주인과 같을 때만** 지웁니다(채팅 자체와 같은 수준의 믿음입니다).
지나간 말은 어차피 서버에 저장되지 않으니, 회수는 '지금 화면에 보이는 것'을 거두는 것입니다.

## 🙋 이름은 신분입니다

한 번 정하면 잠깁니다. 아무 때나 바꿀 수 있으면 랭킹·채팅에서 누가 누군지 알 수 없습니다.

- 처음 정할 때: 8개 화면의 이름 칸 중 아무 데나 적고 칸을 떠나면(또는 Enter) **확인창**이
  뜹니다. 확인해야 확정됩니다. 글자마다 저장하면 "카"만 치고 잠기니 그렇게 하지 않습니다.
- 정한 뒤: 모든 칸이 읽기 전용이 됩니다. 누르면 어디서 바꿀 수 있는지 알려줍니다.
- 바꾸기: **프로필 → ✏️ 이름 바꾸기 (5,000🪙)**. 값은 **새 이름을 정할 때** 빠집니다 —
  중간에 그만두면 지금 이름 그대로이고 코인도 그대로입니다.

**번호가 두 가지 있습니다.** 하나로 합치면 안 됩니다.

| | 언제 만들어지나 | 무엇에 쓰나 |
|---|---|---|
| `myId` | 켤 때마다 새로 | 방 메시지에서 '내가 보낸 것' 가려내기 |
| `playerId` | 기기에 저장 (`jelly_pid`) | 같은 기기로 다시 들어오면 같은 사람으로 알아보기 |

`myId` 를 기기에 저장했다가 **같은 기기의 두 창이 같은 번호**가 되어 서로의 말을 자기
메시지로 알고 전부 무시하는 일이 있었습니다(두 사람 검사에서 6건이 한꺼번에 깨졌습니다).
연결 번호는 창마다 달라야 합니다.

## 💇 머리 모양 (사람 캐릭터)

프로필 → 캐릭터 → **머리 모양**. 사람(🧒👧)을 골랐을 때만 줄이 보입니다.

| | 값 |
|---|---|
| 기본 🙂 | 공짜 |
| 스포츠머리 🏃 | 1,200🪙 |
| 짧은머리 ✂️ | 1,500🪙 |
| 단발 💇 | 2,500🪙 |
| 곱슬머리 🌀 | 3,000🪙 |
| 투블럭 💈 | 3,000🪙 |
| 땋은머리 🧶 | 3,500🪙 |

일곱 가지 모두 남자아이·여자아이 둘 다 고를 수 있어요.

- 산 목록은 이 기기에 저장됩니다(`jelly_hairs`). 설정의 '기록 지우기'를 하면 같이 지워집니다.
- 머리 모양은 방·대기실·랭킹 사진에 **그대로 전달**됩니다. 서버에 새로 넣을 칸은 없습니다.
- 따로 설정할 것은 없습니다.

## ☁️ 계정 — 폰과 노트북을 같은 사람으로 (대시보드에서 두 개 켜기)

지금까지 코인·아이템·이름이 **그 브라우저 안에만** 있었어요. 그래서 한 사람이 폰과
노트북으로 들어오면 남남이었습니다. 이걸 서버로 옮겼습니다.

### 1) SQL 한 덩이 (Supabase → SQL Editor)

```sql
create table if not exists players (
  uid  uuid primary key references auth.users(id) on delete cascade,
  nick text,
  save jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);
alter table players enable row level security;
create policy "내 것만 읽기" on players for select using (auth.uid() = uid);
create policy "내 것만 쓰기" on players for insert with check (auth.uid() = uid);
create policy "내 것만 고치기" on players for update using (auth.uid() = uid) with check (auth.uid() = uid);
```

RLS 덕분에 **남의 코인은 읽지도 쓰지도 못합니다.** 지금까지처럼 기기에만 두면 이걸 막을
방법이 없었어요.

### 2) 대시보드 스위치 (Authentication → Sign In / Providers)

**메일을 안 쓰는 쪽을 기본으로 만들었습니다.** 이메일+비밀번호로 계정을 만들면 메일이
0통 나가고 바로 됩니다 — Supabase 기본 메일의 시간당 한도(무료 2통)에 걸리지 않습니다.
그러려면 **Confirm email 을 꺼야** 합니다.

| 켜고/끄기 | 어디 | 왜 |
|---|---|---|
| **Email** 켜기 | Authentication → Sign In/Up → Email | 이메일+비밀번호로 계정을 만들고 로그인한다 |
| **Confirm email** 끄기 | 같은 화면의 Email 항목 | 켜져 있으면 가입할 때마다 확인 메일이 가서 또 한도에 걸린다. 끄면 **메일 0통**으로 즉시 계정이 생긴다 |
| **Anonymous sign-ins** 켜기 | 같은 화면 | 이메일을 안 넣는 사람의 저장도 서버에 남는다. 그리고 나중에 계정을 만들 때 **그 기록을 그대로 물려받는다** |

Confirm email 을 끄면 남의 이메일 주소로도 가입할 수 있다는 뜻입니다(이메일 소유를
확인하지 않으니까요). 게임 계정에는 흔히 하는 타협입니다 — 이메일은 계정을 찾는
열쇠로만 쓰고, 그 주소로 뭘 보내지도 않습니다. 더 엄격하게 하고 싶으면 나중에 켜면 되고,
그때는 아래 SMTP 를 같이 붙이는 게 좋습니다.

**메일 링크(매직링크)는 보조로 남겨 두었습니다** — 비밀번호를 잊었을 때 쓰라고 작은
단추 두 개로 내려 두었습니다. 그쪽은 여전히 시간당 한도가 있습니다.

### 2-1) 예전 방식(메일 링크)만 쓰고 싶다면



| 켜야 하는 것 | 어디 | 안 켜면 |
|---|---|---|
| **Anonymous sign-ins** | Authentication → Sign In/Up | 저장이 서버로 안 가고 예전처럼 기기에만 남아요(게임은 그대로 돌아갑니다) |
| **Email** (매직링크) | Authentication → Sign In/Up → Email | 이메일로 두 기기를 묶는 것만 안 돼요 |

Authentication → URL Configuration 의 **Site URL** 과 **Redirect URLs** 에 배포 주소를
넣어주세요(예: `https://내주소.netlify.app`). 메일 링크가 돌아올 곳입니다.

⚠️ Redirect URLs 에 **우리 주소만** 넣으세요. `*` 같은 와일드카드를 넣으면 로그인 링크가
남의 사이트로 돌아가게 만들 수 있습니다 — 이 방식에서 가장 중요한 설정입니다.
자세한 것은 `docs/저작권-점검.md` 의 '계정 보안' 부분을 봐주세요.

### ⚠️ 메일 링크를 눌렀는데 "사이트에 연결할 수 없음 / localhost" 가 뜬다면

**Site URL 이 아직 기본값(`http://localhost:3000`)입니다.** Supabase 가 만든 링크가
내 컴퓨터의 3000번 포트로 돌아가려 해서 그렇습니다.

Supabase → **Authentication → URL Configuration** 에서

| 칸 | 넣을 것 |
|---|---|
| **Site URL** | `https://내주소.netlify.app` (배포한 주소 하나) |
| **Redirect URLs** | `https://내주소.netlify.app/**` — 게임이 `/index.html` 로 열려도 돌아올 수 있게 |

바꾼 뒤 **메일을 새로 받아서** 눌러주세요. 이미 받은 링크에는 예전 주소가 박혀 있어서
안 됩니다. (게임 쪽에서도 '지금 열려 있는 주소로 돌아오라'고 같이 보내지만, 그 주소가
Redirect URLs 허용목록에 없으면 Supabase 가 Site URL 로 되돌립니다.)

### ⚠️ "이 기록 지키기"를 눌렀는데 "온라인 기능을 못 불러왔어요" 가 뜬다면

⚙️ 설정의 ☁️ 계정 줄에 **왜 안 되는지**가 적혀 있습니다. 보통 둘 중 하나입니다.

1. **Anonymous sign-ins 를 안 켰다** — 이제 이 경우에도 이메일만 넣으면 계정이 만들어집니다
   (Email 스위치만 켜져 있으면 됩니다). 그래도 켜 두는 게 좋아요 — 이메일을 안 넣는
   사람의 저장도 서버에 남습니다.
2. **`players` 표를 안 만들었다** — 위 SQL 을 먼저 돌려주세요.

미리보기(`file://`)로 열었을 때도 서버 기능은 안 됩니다 — 배포된 주소에서 해주세요.

### ⚠️ 네이버·다음 메일로는 안 옵니다 (구글은 옴)

Supabase 의 **기본 내장 메일은 "테스트용"** 입니다. 공용 도메인에서 나가기 때문에
받는 쪽에서 신뢰도를 못 믿고 버립니다. 지메일은 대체로 들어가지만(스팸함일 수도 있음)
**네이버·다음·한메일은 조용히 버리는 일이 흔합니다.** 우리 코드 문제가 아닙니다.

세 가지 길이 있습니다.

1. **메일을 아예 안 쓴다 (추천 · 이미 만들어 두었습니다)** — ⚙️ 설정 → ☁️ 계정 에서
   **이메일+비밀번호**로 계정을 만드세요. 메일이 한 통도 안 갑니다. **네이버 주소로도
   됩니다** — 주소는 계정을 찾는 이름표로만 쓰고 그 주소로 아무것도 보내지 않으니까요.
   대시보드에서 **Confirm email 을 꺼야** 합니다(안 끄면 가입할 때 확인 메일을 기다립니다).
2. **Custom SMTP 를 붙인다** — Authentication → Emails → SMTP Settings 에 Resend·
   SendGrid·Brevo 같은 것을 넣으면 제대로 인증된 도메인에서 나가서 네이버에도 들어갑니다.
   무료 티어로 충분하고, 시간당 한도도 같이 풀립니다.
3. **지메일로 검증한다** — 급하면 지메일 주소로 테스트하고(스팸함 확인), 배포는 1번으로.

이미 확인 메일을 기다리는 상태로 만들어 버린 계정이 있으면, 게임에서 로그인할 때
"확인 메일을 눌러야 하는 계정이에요" 라고 알려 줍니다. **Confirm email 을 끈 뒤**
Authentication → Users 에서 그 사용자를 지우고 다시 만들거나, 사용자 목록에서
**Confirm user** 를 눌러 주면 됩니다.

### ⚠️ "email rate limit exceeded" — 메일 한도 (개발 중에 제일 자주 만난다)

Supabase 의 **기본 내장 메일 서버는 시간당 몇 통(무료 프로젝트는 보통 2통)** 만 보냅니다.
검증하려고 여러 번 누르면 금세 그 몫을 다 씁니다. 게임에서도 한 번 보내면 **60초 동안은
다시 안 보내게** 막아 두었지만, 시간당 한도는 서버 쪽 것이라 그것만으로는 안 풀립니다.

**개발자로서 검증하는 방법 — 위에서부터 추천 순서입니다.**

| 방법 | 어떻게 | 한도 |
|---|---|---|
| **① Custom SMTP 붙이기** (정석) | Authentication → Emails → SMTP Settings 에 Resend·SendGrid·Mailgun 같은 것을 넣는다. 무료 티어로 충분하다 | 그 서비스 한도(보통 하루 수백~수천 통) |
| **② 대시보드에서 링크를 직접 뽑기** | Authentication → Users → 해당 사용자 → **Send magic link / Generate link**. 메일을 안 거치고 링크를 바로 얻는다 | 없음 |
| **③ 한도를 올리기** | Authentication → Rate Limits → *Rate limit for sending emails* | 프로젝트 등급에 따라 다름 |
| **④ 로컬에서 검증** | `supabase start` (Docker) → 메일이 **Inbucket**(`localhost:54324`)에 그대로 잡힌다 | 없음 |
| ⑤ 그냥 기다리기 | 한 시간쯤 뒤 다시 된다 | — |

②번이 가장 빠릅니다. Users 목록에서 사용자를 만들 때 **Auto Confirm User** 를 켜면
확인 메일도 안 갑니다.

**어디를 봐야 원인이 보이나** — Supabase → **Logs → Auth Logs**. 요청이 실제로 갔는지,
어떤 이유로 막혔는지가 그대로 남습니다. 게임 쪽에서도 ⚙️ 설정 → ☁️ 계정 줄에 사람 말로
옮겨 보여줍니다(`email rate limit exceeded` → "시간당 몇 통만 되니 잠시 뒤에…").

### ⚠️ "이메일·비밀번호가 맞지 않아요" 가 계속 나온다면 → Confirm email 입니다

거의 항상 이것입니다. **Confirm email 이 켜져 있으면 계정이 "확인 대기" 로 만들어지고,
확인 링크를 누르기 전에는 그 이메일로 로그인이 안 됩니다.** 그런데 Supabase 가 주는
오류 문구는 그냥 `Invalid login credentials`("맞지 않아요")여서, 비밀번호를 틀린 것처럼
보입니다. 네이버로 메일이 안 오면 영원히 그 상태입니다.

게임에서는 이제 이렇게 막아 둡니다.

- **계정 만들기를 눌렀을 때** 이메일이 실제로 붙었는지 확인하고, 안 붙었으면 성공이라고
  하지 않습니다 — "⚠️ 이 서버는 확인 메일을 켜 둔 상태예요 … Confirm email 을 끄고 다시" 라고 알려 줍니다.
- **로그인 실패 문구**에도 "확인 메일을 안 누른 계정이에요" 를 같이 적습니다.

**고치는 순서**

1. Supabase → Authentication → Sign In/Up → Email → **Confirm email 끄기**
2. Authentication → **Users** 에서 확인 대기로 남은 사용자를 지운다 (또는 **Confirm user** 를 누른다)
3. 게임에서 다시 **🔐 계정 만들기**

### 비밀번호를 틀리거나 잊으면 — 잠기지는 않습니다

| 걱정 | 실제 |
|---|---|
| 비밀번호를 여러 번 틀리면 계정이 잠기나요? | **아니요.** Supabase 는 틀린 비밀번호로 계정을 잠그지 않습니다. 아주 빨리 여러 번 두드리면 몇 분간 요청이 막힐 뿐이고(기본 5분에 30번쯤), 시간이 지나면 그냥 다시 됩니다. 게임에서도 "여러 번 틀려도 계정은 잠기지 않아요" 라고 적어 둡니다 |
| 메일이 2통뿐이라 비밀번호를 영영 못 찾나요? | **아니요.** '시간당 2통'은 **한 시간마다 다시 채워지는** 한도입니다. 총 2통이 아닙니다 |
| 그럼 진짜 위험한 건? | **메일이 아예 안 오는 것.** 네이버·다음은 Supabase 기본 메일을 버립니다. 이 상태에서 비밀번호를 잊으면 되찾을 길이 없습니다 → **Custom SMTP 를 붙이면 해결됩니다**(위 표 참고) |

비밀번호 찾기 흐름: ⚙️ 설정 → ☁️ 계정 → **🔓 비밀번호 찾기** → 메일 링크로 들어온 뒤
같은 칸에서 **🔐 비밀번호 바꾸기** 로 새로 정합니다.

### 3) 쓰는 법 (⚙️ 설정 → ☁️ 계정)

1. 노트북에서 **⚙️ 설정 → ☁️ 계정** 에 이메일을 넣고 **📧 이 기록 지키기** → 메일함의 링크를 누르면 계정이 지켜져요.
2. 폰에서 같은 이메일을 넣고 **🔑 이 계정으로 들어오기** → 메일 링크를 누르면 **같은 계정**이 됩니다.
   코인·아이템·머리 모양·이름이 그대로 따라옵니다.

비밀번호는 없습니다. 메일로 오는 링크만 누르면 돼요.

### 알아 둘 것

- 서버에 올라가는 것은 **가진 것**뿐입니다: 코인·아이템·산 캐릭터·산 머리 모양·차림새·
  이름·최고점수·출석. 그 기기에서 고른 것(난이도·AI 등급)과 연결 번호는 올라가지 않아요.
- 두 기기에서 따로 놀았으면 **나중에 저장한 쪽이 남습니다**(기기 시계 기준). 한 기기에서
  놀고 다른 기기를 켜면 서버 것을 내려받아요.
- 이미 다른 기기에서 쓰던 계정으로 들어오면 **그 계정 기록으로 바뀝니다.** 지금 기기에서만
  놀던 기록은 그때 대체돼요 — 먼저 '이 기록 지키기'로 이메일을 붙여 두는 게 좋습니다.
- 서버를 못 쓰는 상황(오프라인·스위치 안 켬·미리보기)에서는 **예전처럼 이 기기에만 저장**하고,
  프로필 화면에 왜 그런지 적어 둡니다.
- 계정 칸은 **⚙️ 설정**에 있습니다(프로필 맨 위에 두니 얼굴이 화면 밖으로 밀려서 옮겼어요).
- 같이 쓰는 컴퓨터라면 **🚪 이 기기에서 로그아웃**을 눌러주세요. 세션을 끊고 이 기기에 남은
  기록까지 지웁니다(이메일로 다시 들어오면 그대로 돌아옵니다).
- 랭킹 이름이 겹치는 것은 아직 막지 않았어요(`players.nick` 에 unique 를 걸지 않았습니다).
  두 사람이 같은 이름을 쓰면 저장이 아예 안 되는 쪽이 생겨서, 그건 따로 다뤄야 합니다.
