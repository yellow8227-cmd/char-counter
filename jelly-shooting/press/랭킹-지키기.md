# 랭킹 지키기 — 조작을 어디까지 막을 수 있나

**Supabase 대시보드 → SQL Editor 에 아래를 붙여 넣고 한 번 실행하면 됩니다.**
게임 코드는 이미 준비돼 있어서, 이 SQL 만 돌리면 바로 켜집니다.

---

## 0. 먼저 — 완벽히는 못 막습니다

정직하게 적습니다.

젤리모는 **브라우저에서 전부 도는 게임**이고, Supabase 접속 키(anon key)가 HTML 안에
그대로 들어 있습니다. 그래서 마음먹은 사람은 게임을 열지 않고도 `curl` 한 줄로
점수를 바로 넣을 수 있습니다. **이건 어떤 브라우저 게임도 마찬가지**이고,
막으려면 판을 서버에서 다시 돌려 봐야 합니다(엣지 함수 + 입력 기록 재생).

그래서 목표를 현실적으로 잡았습니다.

> **말이 안 되는 값은 랭킹에 절대 안 올라간다. 콘솔로 하는 장난은 막는다.**

1등이 `999,999,999` 인 랭킹은 아무도 안 봅니다. 그것만 막아도 판은 굴러갑니다.

---

## 1. 세 겹으로 막습니다

| 겹 | 어디서 | 무엇을 막나 | 뚫리나 |
|---|---|---|---|
| ① 게임 코드 | `scoreSane()` | 콘솔로 `score=999999` 하고 죽기 | REST 로 직접 쏘면 뚫림 |
| ② **표 제약(CHECK)** | Postgres | 절대 불가능한 값 | **못 뚫음** |
| ③ **트리거** | Postgres | 시간에 비해 말이 안 되는 점수 · 도배 | **못 뚫음** |

②③ 이 진짜 관문입니다. ① 은 진짜 플레이어의 실수를 줄이는 정도로만 보세요.

---

## 2. 한계를 어떻게 정했나 (추측이 아니라 코드의 값)

게임 코드에서 그대로 뽑았습니다.

```
젤리 하나 점수   pts = 황금이면 26, 아니면 round(40-r)+6  (r=24~34) → 최대 26
콤보 상한        combo ≤ 9
2배점수 아이템   Lv.4 이상이면 ×3
젤리 하나 최대   26 × 9 × 3 = 702점
가장 빠른 스폰   11프레임 (핵불닭 spawnMin) → 초당 5.45개
───────────────────────────────────────────────
이론상 최대      초당 약 3,830점
```

진짜 플레이어를 막으면 안 되므로 **1.5배인 초당 6,000점**으로 잡았습니다.
실제 상위 기록은 한 판 3만 점대(업적 "한 판에서 30,000점")이니 여유가 큽니다.

`🔥 버티기` 판은 값이 점수가 아니라 **초**입니다. 그래서 규칙이 다릅니다 —
`score = dur` 이어야 하고 1시간(3600초)을 못 넘습니다.

## 3. 붙여 넣을 SQL

```sql
-- ── 1) 칸 추가 (있으면 그냥 넘어갑니다)
alter table scores add column if not exists ch  text;   -- 차림새(얼굴)
alter table scores add column if not exists dur int;    -- 그 판을 몇 초 했나
alter table scores add column if not exists pop int;    -- 젤리를 몇 개 터트렸나

-- ── 2) 절대 불가능한 값 막기
alter table scores drop constraint if exists scores_sane;
alter table scores add constraint scores_sane check (
  score >= 0 and score <= 2000000
  and (dur is null or (dur >= 0 and dur <= 7200))
  and (pop is null or (pop >= 0 and pop <= 100000))
  and char_length(name) between 1 and 10
  and char_length(mode) between 1 and 24
);

-- ── 3) 시간에 비해 말이 안 되는 점수 막기 + 도배 막기
create or replace function scores_guard() returns trigger
language plpgsql as $$
declare recent int;
begin
  -- 🔥 버티기 판은 값이 '초'다. 점수 규칙을 그대로 쓰면 안 된다.
  if new.mode = 'fire_time' then
    if new.score < 1 or new.score > 3600 then
      raise exception '버틴 시간이 말이 안 됩니다: %', new.score;
    end if;
    if new.dur is not null and abs(new.score - new.dur) > 1 then
      raise exception '버틴 시간과 판 길이가 다릅니다';
    end if;
  else
    -- 판 길이를 안 보냈으면(옛 버전) 절대 상한만 본다
    if new.dur is null then
      if new.score > 300000 then
        raise exception '점수가 너무 큽니다: %', new.score;
      end if;
    else
      if new.score > 6000 * greatest(new.dur, 1) + 5000 then
        raise exception '% 초에 % 점은 나올 수 없습니다', new.dur, new.score;
      end if;
      if new.mode <> 'endless' and new.score > 300000 then
        raise exception '점수가 너무 큽니다: %', new.score;
      end if;
    end if;
    -- 터트린 개수도 시간과 맞아야 한다 (초당 6개가 물리적 상한)
    if new.dur is not null and new.pop is not null
       and new.pop > 6 * greatest(new.dur, 1) + 20 then
      raise exception '% 초에 % 개는 터트릴 수 없습니다', new.dur, new.pop;
    end if;
  end if;

  -- 도배 막기: 같은 이름으로 1분에 10줄까지
  select count(*) into recent from scores
   where name = new.name and created_at > now() - interval '1 minute';
  if recent >= 10 then
    raise exception '너무 자주 올리고 있습니다';
  end if;

  return new;
end $$;

drop trigger if exists scores_guard_t on scores;
create trigger scores_guard_t before insert on scores
  for each row execute function scores_guard();

-- ── 4) 넣기만 되게. 남의 기록을 고치거나 지우지 못하게 한다.
alter table scores enable row level security;

drop policy if exists scores_read  on scores;
drop policy if exists scores_write on scores;
drop policy if exists scores_edit  on scores;
drop policy if exists scores_del   on scores;

create policy scores_read  on scores for select using (true);
create policy scores_write on scores for insert with check (true);
-- update/delete 정책을 아예 만들지 않는다 = 아무도 못 고치고 못 지운다
```

> `created_at` 칸이 없다면 먼저 한 줄 더:
> `alter table scores add column if not exists created_at timestamptz default now();`

## 4. 돌린 뒤 확인하는 법

SQL Editor 에서 아래를 실행해 보세요. **전부 에러가 나야 정상입니다.**

```sql
insert into scores(name,score,mode,dur,pop) values ('테스트',999999999,'normal',10,10);
-- → 10 초에 999999999 점은 나올 수 없습니다

insert into scores(name,score,mode,dur,pop) values ('테스트',5000,'fire_time',5,10);
-- → 버틴 시간과 판 길이가 다릅니다

update scores set score = 999999 where name = '아무개';
-- → 0 rows (정책이 없어서 아무것도 안 바뀜)
```

정상 기록은 그대로 들어가야 합니다.

```sql
insert into scores(name,score,mode,dur,pop) values ('테스트',12400,'normal',180,420);
-- → 성공
delete from scores where name = '테스트';   -- 대시보드에서는 지워집니다(서비스 키)
```

## 5. 아직 남는 것

| 남는 구멍 | 실제 위험 | 막으려면 |
|---|---|---|
| REST 로 "말이 되는" 가짜 점수를 넣기 (예: 180초에 5만 점) | 중간 | 판을 서버에서 재생해야 함(엣지 함수) |
| 이름을 바꿔 가며 여러 줄 넣기 | 낮음 | 계정당 제한 — 익명 로그인 uid 를 칸에 같이 넣으면 됨 |
| 코인·아이템 조작 | 낮음 | 코인은 남에게 안 보이니 남을 해치지 않음 |

**다음에 한 겹 더 쌓는다면** 익명 로그인 uid(`auth.uid()`)를 `scores` 에 같이 넣고
`with check (auth.uid() = uid)` 로 묶는 것이 가장 값싼 다음 단계입니다.
이름을 바꿔 가며 도배하는 걸 막아 줍니다.
