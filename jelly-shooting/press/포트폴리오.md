- **2부**: 그 틀에 젤리토을 넣어 쓴 **완성 초안** (그대로 복사해서 쓰고, 어색한 문장만 고치면 돼요)

## 1부. 포폴은 이 순서가 잘 읽혀요

읽는 사람(채용 담당·클라이언트·심사위원)은 **30초 안에 "이게 뭐고, 이 사람이 뭘 했나"**를 알고 싶어 해요.
그래서 순서를 이렇게 잡습니다.

| 순서 | 넣을 것 | 분량 | 왜 필요한가 |
|---|---|---|---|
| ① 한 줄 소개 | "무엇을 만든 것"인지 한 문장 | 1줄 | 첫 3초에 이해되지 않으면 안 읽어요 |
| ② 대표 그림 1장 + 영상 | 표지 그림(og.png) + 플레이 화면 | 1장 + 1분 15초 | 글보다 그림이 먼저 읽혀요 |
| ③ 링크 | 지금 바로 해 볼 수 있는 주소 | 1줄 | "실제로 돌아간다"가 가장 강한 증거 |
| ④ 기본 정보 | 기간 · 인원 · 내 역할 · 사용 기술 | 표 4줄 | 규모를 가늠하게 해 줘요 |
| ⑤ 왜 만들었나 | 문제 / 목표 | 3~4줄 | 기획 의도가 있으면 격이 달라져요 |
| ⑥ 무엇을 만들었나 | 기능을 3~6개 덩어리로 | 각 2줄 | 목록이 길면 아무것도 안 남아요 |
| ⑦ 어떻게 만들었나 | 기술 선택 **이유** | 3~5줄 | "왜 그걸 골랐나"가 실력이에요 |
| ⑧ 어려웠던 문제 ★ | 문제 → 원인 → 해결 → **숫자** | 3개 | **포폴의 심장.** 여기만 자세히 |
| ⑨ 배운 것 / 다음 계획 | 솔직하게 | 3줄 | 성장하는 사람으로 보여요 |
| ⑩ 자료 | 스크린샷·영상·문서·저장소 | 목록 | 확인할 길을 열어 두기 |

### 이것만 지켜도 확 좋아져요

1. **숫자를 넣으세요.** "성능을 개선했다" → "한 프레임 1.5ms, 60fps 유지". "AI 난이도를 낮췄다" → "2분 점수 20,406 → 6,576".
2. **문제 → 원인 → 해결** 순서로 쓰세요. 결과만 쓰면 운 좋아 보이고, 원인까지 쓰면 실력으로 보여요.
3. **내가 한 일과 도구가 한 일을 구분**하세요. 정직한 포폴이 더 신뢰받아요.
4. **기능 자랑보다 판단 자랑.** "무엇을 안 넣었는지"도 판단이에요. (예: 광고·결제를 안 넣은 이유)
5. **길이는 A4 2~3장.** 더 길면 ⑧만 읽혀요. 그래서 ⑧을 제일 잘 써야 해요.
6. **그림은 실제 화면.** 손으로 그린 목업은 실물과 달라져서 나중에 거짓말이 돼요.

### 어디에 올릴까

- **노션 한 페이지**가 가장 편해요(수정도 쉽고, 링크 하나로 공유돼요).
- 파일로 낼 일이 있으면 **노션 → PDF 내보내기**.
- 사진은 `press/shots/` 안의 스크린샷을, 영상은 `press/video/`의 영상을 그대로 쓰면 돼요.
- 소개 페이지(`press/index.html`)는 그 자체로 **포트폴리오 랜딩 페이지**로 써도 됩니다.

> 친구와 방 코드를 나눠서 2~4명이 실시간으로 대전합니다.

> 가장 오래 붙잡은 문제는 세 가지였어요. 첫째, 아이폰에서 판이 미세하게 커졌다 작아지는 문제 —

> 셋째, 화면이 스스로 깨지는 걸 못 잡는 문제 — 화면 넘침·작은 버튼·2인 통신을 자동으로 검사하는
> 도구를 같이 만들어서, 고칠 때마다 검사를 돌립니다.
> 이 소개 페이지의 스크린샷과 영상도 그 도구가 실제 게임을 플레이해서 만든 거예요."

**설치 없이 웹에서 바로 하는 캐주얼 아케이드 게임. 떨어지는 젤리를 톡 터트려 콤보를 쌓고, 친구와 실시간으로 대전합니다.**

## 왜 만들었나

아이와 같이 할 게임을 찾다가, **광고가 없고 · 설치가 필요 없고 · 3분 만에 한 판이 끝나는** 게임이
생각보다 없다는 걸 알았어요. 그래서 직접 만들기로 했습니다.

목표는 세 가지였어요.

1. **문턱 0** — 주소만 열면 시작. 설치·회원가입·결제 없이.
2. **혼자도 재미있고, 둘이면 더 재미있게** — 같은 판을 두 명 이상이 동시에 겨루기.
3. **결과가 남을 것** — 점수 숫자만 남기지 않고, 이긴 사람·진 사람의 장면을 그림으로 남기기.

## 무엇을 만들었나

- **혼자 하기** — 난이도 4단계(순한맛·보통맛·매운맛·핵불닭), 콤보, 폭탄, 5종 아이템, 기록 저장
- **실시간 던전** — 방 코드로 2~4명이 같은 판에서 동시 대전. 게이지를 모아 지그재그·안개·스피드업 같은 **방해**를 상대에게 던져요
- **던지기 게임** — 한 명은 젤리를 던지고 한 명은 터뜨리는 비대칭 대전. 다시 할 때 **역할 바꾸기** 가능
- **AI와 대결** — 인터넷 상대가 없어도 되는 4단계 AI. 다시 할 때 **실력·역할 변경** 가능
- **꾸미기 / 창작소** — 캐릭터 6종 × 머리 × 색 × 악세서리, 코인으로 아이템·나만의 악세서리 제작
- **결과 화면** — 이기면 춤추고 지면 분해하는 **승패 애니메이션**(표정·자세·말풍선이 판마다 랜덤), 진 사람은 이긴 사람 화면 **관전**, 결과를 **그림으로 공유**
- **PWA** — 홈 화면에 추가하면 앱처럼 전체화면. 오프라인에서도 혼자 하기는 동작

## 어떻게 만들었나 (그리고 왜)

- **게임 엔진을 쓰지 않았다.** 젤리·캐릭터·표정까지 캔버스에 직접 그립니다. 엔진을 얹으면
  로딩이 커지고 "왜 이렇게 움직이는지"를 제가 설명할 수 없게 돼요. 문턱 0이라는 목표와도 맞지 않았습니다.
- **파일 하나로 배포.** `index.html` 안에 화면·소리·통신·저장이 다 들어 있어 정적 호스팅에 올리면 그게 배포예요.
  빌드 도구가 없으니 반년 뒤에 열어도 그대로 돌아갑니다.
- **실시간은 Supabase Realtime 브로드캐스트.** 서버를 직접 운영하지 않고도 방·점수·방해·관전을 주고받아요.
  게임 판정은 각자 기기에서 하고, 오가는 것은 "무엇이 일어났다"는 소식뿐이라 지연에 관대합니다.
- **소리는 Web Audio로 합성.** 음원 파일이 없어 용량이 늘지 않고, 승리 팡파레·패배 효과음도 코드로 만듭니다.

## 어려웠던 문제 ★

### ① 아이폰에서 판이 미세하게 커졌다 작아졌다 했다

- **증상**: 플레이 중 판(캔버스)이 흔들리듯 크기가 변함. 실측 299×449 → 263×395.
- **원인**: 아이템을 다 쓰면 아래 아이템 칸이 사라져 **아래 띠 높이가 줄고**, 그만큼 판이 커졌다.
  게다가 아이폰의 노치·홈바 영역(safe-area)까지 겹쳐 계산이 매 프레임 달라졌다.
- **해결**: 판이 시작될 때 위·아래 띠 높이를 **실측해서 못 박고**(`bandsLock`), 한 판 동안 판 크기를 **얼렸다**(`boardLock`).
  줄어드는 방향(상대가 들어와 줄이 늘어날 때)만 따라가게 해서 왔다갔다하지 않게 했다.
- **결과**: 폭 360·390·430 세 가지와 기기 6종 × 화면 7개를 자동 검사해 한 판 동안 판 크기가 변하지 않음을 확인.

### ② AI가 너무 강해서 사람이 이길 수 없었다

- **증상**: "연습조차 어렵다." 가장 쉬운 단계 AI도 사람을 앞질렀다.
- **원인**: AI 점수를 **초당 점수(dps)**로 계산했는데 가장 쉬운 단계가 초당 170점,
  즉 **2분에 20,406점**을 냈다. 사람의 평균 실력을 훨씬 넘는 값이었다.
- **해결**: AI를 눈으로 보이는 행동(맞히는 확률·던지는 간격·폭탄 실수·방해 쿨타임)으로 다시 짜고,
  4단계를 **실제로 재서** 잡았다. 그리고 검사 도구에 "2분에 몇 점 / 젤리 몇 개"를 10회 평균으로 재는 검사를 추가했다.
- **결과**: 2분 점수 **20,406 → 6,576**(가장 쉬운 단계), 단계별 젤리 처리 수 **6 / 11 / 23 / 42개**로 단조 증가.
  "가장 쉬운 단계는 초보가 이기고, 가장 센 단계는 잘하는 사람이 겨우 이긴다"는 목표에 맞췄다.

### ③ 상대 탈락 알림이 화면을 가렸다

- **증상**: 대전 중 "친구 탈락!" 쪽지가 **네 개까지 겹쳐 쌓여** 판을 덮었다.
- **원인**: 같은 소식이 여러 번 도착하는데 **중복을 걸러내지 않았고**, 알림을 판 위에 얹고 있었다.
- **해결**: 판 위 알림 자리를 **없애고**, 정보를 판 밖 상대 칩에 붙였다(💀 표시 + 반짝임).
  이미 알린 사람은 다시 알리지 않게 기록했다.
- **결과**: 판을 덮는 요소 0개, 알림 때문에 판 크기가 바뀌지 않음, 같은 소식 5번에도 반응 1번 —
  이 세 가지를 자동 검사로 고정했다. (2~4인 × 폭 3종, 12가지 조합 검증)

## 특별히 신경 쓴 것

- **캐릭터 6종의 몸 비율을 종마다 따로 잡았다.** 처음엔 팔이 얼굴에 비해 너무 얇고 길어
  "긴팔 원숭이" 같았고, 고양이 꼬리가 어깨 위로 올라와 **팔이 세 개**로 보이는 문제도 있었다.
  팔 길이·굵기·손 모양, 꼬리 위치를 종마다 다시 잡아 수치로 검사(팔 너비 3.13R → 2.92R, 꼬리 위치 0.47R → 1.02R)한다.
- **자동 검사 도구를 같이 만들었다.** 화면 넘침·작은 버튼·CSS 충돌, 아이폰 safe-area,
  2인/4인 실시간 통신, AI 난이도, 프레임 시간(1.5ms/프레임)까지 스크립트로 검사한다.
- **이 포폴의 그림과 영상도 스크립트가 만든다.** 게임을 실제로 띄우고 진짜로 눌러 플레이한 화면을
  녹화·촬영해서 스토어용 스크린샷과 소개 영상을 뽑는다. 게임을 고치면 다시 돌리면 끝.
